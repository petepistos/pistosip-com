Security Baseline

AMS360 Minimum Security Baseline

The settings every Pistos client's AMS360 should have, where to find them, and how to prove they are on.

Product: Vertafore AMS360 with VSSOAudience: Agency owners, office managers, IT providersFramework: CIS Controls v8.1, IG1Version: 1.0, November 2026

AMS360 holds every client's personal details, policies and accounting. This page sets the minimum security settings Pistos expects in Vertafore AMS360. Most logins now run through Vertafore Single Sign-On (VSSO), so some settings live in AMS360's Agency Setup and some in the VSSO Admin Console. Each item says which.

How to read this

Minimum items are required for a Pistos client. Recommended items are what we set up when the agency agrees. Each item names the CIS Controls v8.1 safeguard it supports, so it lines up with the PCS risk assessment.

The standards

1

One named login for every person

MinimumCIS v8.1: 4.7, 5.1
Where

AMS360: Employee Center. VSSO: Manage Users

The standard
  • Every person who uses AMS360 has their own login in their own name, in both Employee Setup and VSSO.
  • No shared logins, and none left over from a past employee, a vendor or a trainer.
How to check it

Compare the VSSO user list and the AMS360 licensed users with the PCS staff roster.

2

Multi-factor authentication on for everyone

MinimumCIS v8.1: 6.3, 6.5
Where

VSSO Admin Console (360 Toolbox > Vertafore Single Sign-On), or the agency's own sign-in if AMS360 uses federated sign-on (FSSO) with Microsoft 365

The standard
  • Every user signs in with a second step.
  • Preferred: connect AMS360 to Microsoft 365 through federated sign-on, so the agency's Microsoft MFA and Conditional Access rules cover AMS360 too.
  • Otherwise: require MFA for every user in VSSO.
What the product can't do, and what to do instead

Vertafore's public help does not show how an administrator forces MFA for every user. Ask Vertafore support to confirm it is required for the agency, and keep their answer in PCS. Federated sign-on through Microsoft 365 avoids the question.

How to check it

Sign in from a new browser. AMS360 or Microsoft should ask for a second step.

3

Two System Admins at most

MinimumCIS v8.1: 5.4
Where

AMS360: Employee Center > employee > Edit Employee > Security

The standard
  • No more than two people in the System Admin or Owner security groups.
  • Pistos's administrator login is used only for administration, never for daily work.
  • Security Group Setup is limited to those two people.
How to check it

List the members of the System Admin and Owner groups.

4

Strong, unique passwords

MinimumCIS v8.1: 5.2
Where

Agency Setup > System Configuration Options > Agency Password Setup (native logins). VSSO users follow VSSO's password policy.

The standard
  • Agency Password Setup at its strictest available length, complexity and history.
  • By policy: at least 14 characters, not used for any other system, stored in a password manager.
How to check it

Review Agency Password Setup and the signed PCS line-of-business access form.

5

Session timeout at 15 minutes

MinimumCIS v8.1: 4.3
Where

Agency Setup > System Configuration Options > Set Session Timeout to

The standard
  • Set to 15 minutes. The default is 20.
How to check it

Leave AMS360 idle for 15 minutes. It should close the session.

6

Customer visibility limited

RecommendedCIS v8.1: 3.3
Where

Agency Setup > System Configuration Options > Customer Search Results

The standard
  • Turn on Only show logged in user Customers based on Business Unit, Service Group and Secured Customer settings, where the agency is set up for it.
  • Use Customer Setup > Assign Employees for sensitive accounts.
How to check it

A CSR searching outside their book should see names only, or nothing.

7

Security groups match the job

MinimumCIS v8.1: 3.3, 5.4
Where

Agency Setup > Security Group Setup; Bank Setup > Employee Authorizations

The standard
  • Create a custom group for each role (for example CSR, Producer, Accounting) instead of putting everyone in Exec or Owner.
  • Give No Access to Employee Setup, Company Setup and security sections for everyone except the administrators.
  • Limit access to bank accounts with Employee Authorizations to the bookkeeper and owner.
  • Limit who can see or export customer tax ID and Social Security numbers to the people who need them, using the group's secured items.
What the product can't do, and what to do instead

Vertafore's public help does not spell out which secured items control tax ID visibility and export. Confirm the exact items with Vertafore support during setup.

How to check it

Print the Secured Items list for each group once a quarter and keep the reviewed copy in PCS. Changes take effect at the user's next login.

8

Login hours limited

RecommendedCIS v8.1: 6.1
Where

VSSO Admin Console > Manage Users > user > Product Access > AMS360

The standard
  • New AMS360 users default to weekday hours (Monday to Friday, 8 AM to 5 PM). Keep that default unless a person's job needs more, and record why.
How to check it

Review who has 24-hour access each quarter.

9

Leavers turned off the same day

MinimumCIS v8.1: 5.3, 6.2
Where

AMS360: Employee Center > employee > Edit Employee > Security > Login Information. Also VSSO: Manage Users.

The standard
  • On the person's last day, remove their User ID and Password (native logins) or change Access Type to Services Access (single sign-on users), and remove or disable them in VSSO.
  • Any account nobody has signed in to for 45 days is reviewed and turned off if it is not needed.
How to check it

Each month, compare licensed users with the PCS roster.

10

Sign-in history kept and reviewed

MinimumCIS v8.1: 8.2, 8.3
Where

Agency Setup > System Configuration Options > Retain Authentication Information for

The standard
  • Set to 1 year or more. The default is 90 days.
  • Once a month, review login activity for odd hours, unknown places, and people who have left.
How to check it

The retention setting shows 1 year or more, and the monthly review is noted in PCS.

11

Vendor security and backup evidence on file

MinimumCIS v8.1: 11.2, 11.3, 11.4, 15.1
The standard
  • Vertafore is listed as a vendor in PCS with an agency contact.
  • Vertafore's current security report (SOC 2 or equivalent) and backup statement are uploaded to PCS and renewed when they expire.
How to check it

PCS shows the vendor evidence as received and not expired.

Sign-off checklist

  • VSSO and Employee Setup match the staff roster; no shared, vendor or leftover logins
  • MFA required for every user (VSSO or Microsoft 365 federated sign-on), confirmed in writing
  • Two or fewer System Admin or Owner members
  • Agency Password Setup at its strictest; password rule signed on the PCS form
  • Session timeout set to 15 minutes
  • Role-based security groups; bank access limited by Employee Authorizations
  • Leaver process and 45-day dormant review in place
  • Authentication history kept for a year and reviewed monthly
  • Vertafore security and backup evidence in PCS
